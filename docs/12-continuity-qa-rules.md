# 12. 연속성·검수 규칙

모듈: `planner.preflight`(P), `qa.py`(CQ·RS·비용). 규칙 ID는 코드와 1:1.

## 기획안 사전 점검(S03 → G1)

| ID | 항목 | 실패 시 |
|---|---|---|
| P01 | 컷 길이 합계 = 러닝타임(±0.5초) | fail |
| P02 | 씬 타임라인 연속(빈틈·겹침 없음) | fail |
| P03 | 대사 밀도 초당 5음절 이하 | warn |
| P04 | 등장인물 ≤ 4, 공간 ≤ 3(AI 일관성) | warn |
| P05 | 화자가 캐릭터 목록에 있음 | fail |
| P06 | 최소 컷 길이 0.5초 | warn |
| P07 | 반전·회수 서사의 복선 단서 | review(사람 확인) |

G1은 fail이 하나라도 있으면 `blocked`.

| CQ06 | L3 | 같은 씬에서 조명 상태 변화 | warn |
| CQ07 | L3 | 대사 밀도 초당 5음절 이하 | warn |

| RS04 | L5 | AI 생성 표기는 게시 시 플랫폼 기능으로(영상 내 코너 라벨 없음) | info |

G2: error가 있으면 `blocked`, 없으면 승인(또는 사전 위임) 대기.

## 시험된 실제 사례

예시 기획안 첫 버전에서 컷 5가 "이력서를 든" 상태로 시작했지만 컷 4 끝에는 손이 비어 있었다 → CQ02가 잡았다. 컷 4 시작에 이력서를 쥐게 고쳐 통과. 테스트 `test_deliberate_prop_discontinuity_detected`는 펜을 오른손→왼손으로 옮겨 같은 오류를 재현한다.

## S10 최종 검수(스킬 담당)

실제 영상의 카메라·싱크·컷 경계·전체 흐름은 `video-production-assets`의 R20 카메라 QA와 연속성 게이트로 검사하고 결과를 `reviews/final_qa.json`에 쓴 뒤 `complete S10_qa --evidence`로 넘긴다. 파일 존재·디코드 성공은 연속성 증거가 아니다.
