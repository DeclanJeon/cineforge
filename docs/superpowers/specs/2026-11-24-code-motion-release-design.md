# CineForge 코드 모션 연동 릴리스 설계

상태: 구현 작업본 · 릴리스 미실행. 설치 wheel로 실제 HTML 렌더와 혼합 조립·납품 경로를 자동 시험했다. 기존 실사 테이크 대신 테스트용 영상, 승인 및 사람 재생 보고는 테스트 입력을 사용했다. 실제 실사 테이크와 사람 검수는 릴리스 전 남은 검증이다.

## 목표와 현재 상태

배포된 `contents-production-skills`의 HTML 렌더 및 제출 검사를 설치된 CineForge CLI와 함께 사용한다. 출시 검증은 실제 MP4 접수에서 멈추지 않고 컷 채택·조립·사람 재생 검수·납품까지 이어진다. 현재 `main` 커밋(`2ab67bc`)에는 `code-motion` 실행 레인이 없고, 로컬 변경에 레인·봉투·선택적 `motion_brief` 초안과 테스트가 있다. 작업본이 배포되었다고 간주하지 않는다. 기존 `2026-11-24-skill-pack-integration-design.md`의 선언형 팩 장착·고정 계약은 별도 과제다.

## 선택지

1. 로컬 변경만 정리해 게시: 가장 작지만, 컷별 경로와 프로젝트 전체 `video_cut` 레인 사이의 간극, 실물 최종 납품 검증이 남는다.
2. **권장: 좁은 호환 릴리스.** 기존 0원 레인·결과 접수 계약을 정리하고, 한 프로젝트에서 로컬 코드 모션과 기존 실사 테이크를 합친 실제 납품 경로를 검증한다. 렌더러와 제작 판단은 팩에 둔다.
3. 선언형 팩 통합을 한꺼번에 도입: 장기 방향에는 맞지만 이번 릴리스의 승인·재개·레거시 테스트 범위를 크게 늘린다. 별도로 진행한다.

## 계약과 경계

- **스킬팩:** 컷 감지, 연출과 구현 브리프, HTML 렌더, 출력 길이·종횡비·선택적 해상도/FPS·디코딩 검사. 현재 팩의 `submit_code_motion.py PROJECT --file RESULTS.json` 인터페이스를 바꾸지 않는다.
- **CineForge:** 승인된 실행 계획과 봉투를 발행하고 로컬 결과 파일의 영수증·해시를 유지한다. `code-motion`은 `video_cut`에서만 허용, 모델 `html-seek-v1`, 비용/견적 필드 금지, `max_jobs`와 기존 실행 승인 적용. `execute`는 실행 봉투만 만들고 HTML이나 팩 코드, 네트워크 호출을 자동 실행하지 않는다.
- **컷 범위:** 현재 v1은 `video_cut` 레인 하나만 허용한다. 이번 릴리스는 한 봉투에서 유료 생성 공급자와 코드 모션을 섞지 않는다. 대신 코드 레인에 승인 해시로 고정되는 선택적 `cut_ids`를 추가한다. 배열은 비어 있거나 중복일 수 없고 검증된 프로젝트 컷 ID만 허용한다. 미지정은 호환용 전체 코드 모션이며, 브리프가 있다면 모든 대상이 `code`일 때만 허용한다. 지정된 컷만 봉투를 생성하고 `max_jobs`는 필터 후 적용한다. 브리프가 있고 선택과 `route_by_cut`의 `code` 항목이 다르면 중단한다. 나머지 컷은 기존 승인된 테이크를 채택한다. 선택 목록 없이 실사 컷까지 코드 모션으로 조용히 전환하지 않는다. 전체 로컬 레시피의 기존 `cineforge motion` 경로는 유지한다.
- **접수:** CLI 직접 사용에서도 `code-motion`의 `accepted`는 봉투에 있는 컷, 프로젝트 내부 실제 파일, 영상 스트림·길이·종횡비를 요구한다. 이는 팩 검사 중복이 아니라 엔진에 영수증이 들어오는 마지막 경계다. 기존 팩의 전체 디코딩/프레임 QA는 그대로 둔다. 요구값은 승인된 봉투에서 읽고, 출력이 맞지 않으면 영수증을 쓰지 않는다. 타 공급자의 테이크 정책은 변경하지 않는다. 기존 봉투·영수증의 읽기 및 과거 납품 조회는 유지한다.
- **채택·납품:** `accepted`를 자동 채택으로 해석하지 않는다. 코드 모션 컷의 채택은 동일 경로·해시의 접수된 테이크인지 확인한 뒤 기존 테이크/편집/조립 계약으로 넘긴다. 파일 변경이나 잘못된 컷 매핑은 차단한다. 기존 실사 테이크 채택 규칙과 재생 검수·최종 납품 해시 게이트는 유지한다. `motion_brief`는 선택적 인계 근거이지 실행 권한이 아니다.

## 구현·배포 순서

1. 로컬 모션 변경과 다른 작업을 분리하고 `main` 기준으로 범위를 고정한다. 팩 독립 배포 설계나 다른 작업은 포함하지 않는다.
2. 승인·컷 선택·접수/채택의 실패 테스트를 먼저 작성한다. 필요한 변경은 `execution_plan.py`, `jobs.py`, 테이크 채택 모듈과 직접 테스트에 한정한다. 스키마/가이드는 기존 로컬 변경 중 필요한 부분만 정리한다.
3. 임시 설치에서 같은 스킬팩을 사용해 공인 로컬 MP4 두 컷(실사 테이크 + 코드 모션)을 한 프로젝트로 조립한다. 승인 없는 실행, 오규격 접수, 변조, 잘못된 채택을 각각 확인한다. 실제 사람이 재생을 확인하기 전에는 검수 통과/납품으로 기록하지 않는다.
4. 전체 회귀 후 wheel을 새 환경에 설치해 소스 체크아웃 없이 동일 테스트를 반복한다. 호환 CLI 버전과 스킬팩 커밋을 문서에 기록한다. 별도 승인 전에는 원격 게시·배포를 하지 않는다.

## 인수 기준

| 시나리오 | 합격 기준 |
|---|---|
| 범위/권한 | 미승인, 만료, 컷 목록 변경, 비용 필드, 모르는 컷·중복 컷은 차단. 과거 프로젝트/타 공급자/전체 로컬 레시피 회귀 통과 |
| 정상 접수 | 설치된 팩이 만든 4초 9:16 MP4만 해당 테스트 컷의 접수·채택 기록에 연결 |
| 잘못된 접수 | 가로 30초 MP4, 영상 없는 파일, 올바른 방향이지만 잘못된 길이, 접수 후 바뀐 내용은 접수/채택 경계에서 해당 변경을 남기지 않고 차단 |
| 실제 혼합 납품 | 기존 실사 테이크 1개 + 코드 모션 컷 1개를 실제 MP4로 조립. 독립 디코딩과 컷 경계 확인. 사람 재생 검수 전 납품 차단, 승인된 최종 해시로만 납품 |
| 새 설치 | wheel과 배포된 팩으로 위 흐름 재현. 엔진이 팩 렌더러·가이드를 내장하거나 자동 실행하지 않음 |
